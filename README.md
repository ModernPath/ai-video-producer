# AI Video Producer

Turn a sentence into a short film.

You describe the film you want — *"a 1-minute piece about our platform, directed like a Kaurismäki
comedy, a bit humoristic"* — and the system compiles that into **directable craft**: framing, camera
movement, palette, pacing, and what the style refuses to do. It then drafts a script, breaks it into
shots, casts the people and the places, generates frames and video, and assembles a cut with music.

Built on Google's Gemini family (text, image, video) with local [Remotion](https://remotion.dev)
renders for graphics.

> **Status: a working development build, not a product.** It makes real films and spends real money.
> Authentication is designed but not implemented ([ADR-005](docs/adr/005-session-cookie-auth.md)),
> there is a single local dev organisation, and many requirements are awaiting review.
> [`docs/88-architecture-review.md`](docs/88-architecture-review.md) is an honest account of where
> the code is weak.

## What makes it different

**Style is data, not a prompt.** A free-form brief compiles — via grounded web search — into a
**Style Card**: typed axes for camera, pacing, palette, light, performance, humour, continuity, and
`antiNotes`, the things the style *refuses*. Every downstream prompt derives from that card. A named
reference director is resolved into craft primitives at compile time and
[never reaches an image model](docs/adr/011-reference-names-never-reach-a-model.md) — because a name
averages to mush in a diffusion model, while "frontal, locked-off, saturated red against olive"
repeats reliably across every shot.

**Consistency comes from reference images, not adjectives.** Characters, products *and locations* are
cast as entities with reference images, and each shot is conditioned only on the cast actually in it.
Shots that continue one another hand over the previous take's **last frame** as the next shot's
first, so poses and wardrobe survive a cut.
([ADR-012](docs/adr/012-consistency-by-reference-not-description.md))

**Craft is checkable.** Shot grammar — size, angle, movement — is typed, so a plan can be *graded*:
two identical framings in a row, a line too long to speak inside its shot, a film that ends on a cut
instead of a hold. Four independent reviewers (pacing, continuity, casting, story) critique the
script and the shot plan before anything is generated.

**Nothing is generated by accident.** Requests are refused where they would be wasted: a sub-clip's
start frame is given rather than bought, and a chained shot cannot generate before its source has a
chosen take.

## Quickstart

Requires Node ≥ 22, pnpm and Docker.

```bash
pnpm install
cp .env.example .env          # local docker defaults; add GEMINI_API_KEY for real generation
pnpm compose:up               # Postgres + MinIO
pnpm migrate
pnpm --filter @avd/web dev    # http://localhost:3300
```

`MOCK_GEN=1` is the default: fixtures, no API calls, no cost. Unset it and provide a
`GEMINI_API_KEY` to generate for real.

**Real generation costs money.** Video dominates at roughly **$0.10 per second**; text and local
Remotion renders are effectively free. A per-organisation daily cap is enforced
(`GEN_DAILY_USD_CAP`, default $100).

```bash
pnpm test                                  # full suite
pnpm style --seed cinematic-mood           # inspect a built-in Style Card, no API call
pnpm style --plan "a 30s film shot like a nature documentary"   # compile + plan, ~$0.002
pnpm audit:prompts <projectId>             # verify stored prompts against the plan
```

### Running the worker

By default generation runs **inline**, inside the web request — simple, but a page reload can strand
a take. For anything beyond casual use:

```bash
WORKER_MODE=queue pnpm --filter @avd/web dev
pnpm --filter @avd/worker dev
```

## Architecture

A pnpm monorepo. Domain logic lives in `libs/<context>` and is imported by both apps; libs never
import apps.

| Context | Owns |
|---|---|
| `plt` | organisations, quota |
| `prj` | projects, style cards, cost meter |
| `stb` | script, shot plan, shots, takes, casting, continuity, critique |
| `gen` | generation ledger, provider routing, prompt assembly |
| `ast` | assets, entities, style kits, storage |
| `asm` | assembly, export, share links |
| `anm` | Remotion compositions — title, kinetic, stat, quote, checklist |
| `shared` | config and contracts — the **only** home for model ids, prices and thresholds |

Postgres with a schema per context, S3-compatible object storage, ffmpeg via Docker, SSE for
progress. Decisions are recorded in [`docs/adr/`](docs/adr/).

## How this repo is built

The process is itself part of the artifact. Every requirement carries acceptance criteria with tests
and code cross-linked, and every session's discoveries are written down.

| File | Role |
|---|---|
| [`CLAUDE.md`](CLAUDE.md) | the process manual — non-negotiables, build loop, what to test where |
| [`AGENTS.md`](AGENTS.md) | agent entry point |
| [`prompts.md`](prompts.md) | copy-paste prompts, including the architecture-baseline and review passes |
| `libs/<ctx>/REQUIREMENTS.md` | requirement ledgers with status and traceability |
| `libs/<ctx>/LOG.md` | append-only build logs — 120+ recorded discoveries, with reasoning |
| [`docs/adr/`](docs/adr/) | architecture decision records, including the reversals |
| [`docs/88-architecture-review.md`](docs/88-architecture-review.md) | a candid review of this codebase |

The logs and ADRs record mistakes as carefully as successes — including a prompt-assembly design
that shipped four user-visible defects before it was caught, and the reasoning that missed it. If
you are interested in how AI-assisted development actually goes, that material is more honest than
most.
